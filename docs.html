Démarrage rapide

Sur un VPS Debian/Ubuntu fraîchement installé (root ou sudo) :

curl -fsSL https://install.vpscontrol.lordobitotech.xyz | sudo bash

Le script installe Docker et Go automatiquement si nécessaire, compile le panel, crée les dossiers de travail et installe un service systemd qui démarre VPS Control automatiquement (y compris après un redémarrage du serveur).

Par défaut, le panel écoute uniquement sur 127.0.0.1:8090 (pas exposé à internet). Pour tester immédiatement sans domaine, ouvrez un tunnel SSH depuis votre machine :

ssh -L 8090:localhost:8090 root@VOTRE_IP
# puis ouvrez http://localhost:8090

À la première visite, un écran vous invite à créer le premier compte administrateur du panel — un identifiant propre à VPS Control, distinct de vos accès SSH/root.

Domaine & HTTPS

Pour exposer le panel proprement sur internet avec un certificat HTTPS automatique, passez votre domaine à l'installeur :

curl -fsSL https://install.vpscontrol.lordobitotech.xyz | sudo bash -s -- panel.mondomaine.com
Pensez à pointer un enregistrement DNS de type A de votre domaine vers l'adresse IP du VPS avant ou juste après cette commande. Caddy (installé automatiquement) obtiendra et renouvellera le certificat HTTPS tout seul dès que le DNS résout correctement.

Si vous avez déjà installé le panel sans domaine, vous pouvez relancer l'installeur plus tard avec un domaine : il détecte l'installation existante et se contente d'ajouter la configuration du reverse proxy.

Vous préférez gérer votre propre reverse proxy (Nginx, Traefik...) ? Pointez-le simplement vers 127.0.0.1:8090 et laissez le champ domaine vide lors de l'installation.

Variables d'environnement

Modifiables dans /etc/systemd/system/vpscontrol.service puis systemctl daemon-reload && systemctl restart vpscontrol.

VariablePar défautRôle
VPSCONTROL_LISTEN127.0.0.1:8090Adresse d'écoute du panel
VPSCONTROL_DATA_DIR/opt/vpscontrol/dataComptes, connexions DB, déploiements (JSON)
VPSCONTROL_DEPLOY_ROOT/opt/vpscontrol/appsDossier des applications déployées
VPSCONTROL_FILES_ROOT/homeRacine exposée par le gestionnaire de fichiers

Fonctionnalités

  • Comptes admin propres au panel, séparés du SSH/root, multi-comptes (admin / lecture seule)
  • Gestionnaire de fichiers web complet (parcourir, éditer, uploader, télécharger, supprimer)
  • Gestion des services Docker (start/stop/restart/suppression, logs)
  • Déploiement depuis un dépôt GitHub public ou un fichier .zip, avec détection automatique du stack
  • Création rapide d'une base MySQL ou PostgreSQL en conteneur
  • Navigateur de base de données (tables, lignes, requêtes SQL libres)

Architecture

Le panel est un unique binaire Go : le frontend (HTML/CSS/JS vanilla) est embarqué dedans via go:embed, donc rien à installer côté Node ou build step. Les comptes, connexions aux bases et déploiements sont stockés dans un simple fichier JSON local — pas de base de données à faire tourner pour le panel lui-même. Chaque application déployée tourne dans son propre conteneur Docker, ce qui isole les apps entre elles et permet au panel de piloter leur cycle de vie (start/stop/ restart) via la CLI Docker.

Limites connues

  • Un conteneur par application — pas d'orchestration multi-conteneurs automatique (pas de docker-compose généré)
  • Les mots de passe de connexion aux bases de données sont stockés en clair dans le fichier JSON local (permissions restreintes à root)
  • Pas encore de logs de build en direct pendant un déploiement
  • Le service tourne en root pour piloter Docker et parcourir les fichiers du système
  • Pas de rôles fins par déploiement (un compte "lecture seule" voit tout, sans découpage par projet)

Roadmap

  • Logs de build en streaming pendant le déploiement
  • Chiffrement au repos des mots de passe de connexions aux bases
  • Templates docker-compose pour les stacks multi-conteneurs (app + DB + cache)
  • Webhooks GitHub pour redéployer automatiquement à chaque push
  • Historique des déploiements avec rollback
  • Statistiques CPU/RAM par conteneur sur le tableau de bord
